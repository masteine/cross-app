# Профілі сумісності

Профіль сумісності описує, як запускати конкретну гру чи програму, щоб вона працювала без ручних дій: який графічний бекенд, які залежності, змінні середовища, DLL overrides, аргументи і відомі проблеми. Мета v0.1: для ігор з профілем не потрібні ручні правки реєстру чи env (розділ 4 [плану](../SPRINT_PLAN.md)).

> **Статус документа.** Формат профілю визначає Спринт 7 (крейт `cross-compat`), він розробляється паралельно з цим текстом. Тут описано **концепцію** і те, що вже працює. Місця, які треба звірити з фінальним форматом, позначено **[узгодити зі Спринтом 7]**.

## 1. Що вже є в бета-версії

Налаштування окремої гри Steam зберігаються в `bottle.toml` пляшки і задаються командою `cross steam profile`:

```bash
cross deps install steam dxvk
cross steam profile steam 220 --backend dxvk --env DXVK_HUD=fps --arg -novid
cross steam profile steam 220            # показати
cross steam profile steam 220 --env DXVK_HUD=   # прибрати змінну
cross steam profile steam 220 --clear    # прибрати все
```

У `bottle.toml` це виглядає так (поля `LaunchProfile` з `cross-core`):

```toml
[[apps]]
name = "Half-Life 2"
path = 'C:\Program Files (x86)\Steam\steam.exe'
steam_appid = 220

[apps.profile]
args = ["-novid"]
backend = "dxvk"            # або "d3dmetal"

[apps.profile.env]
DXVK_HUD = "fps"

[apps.profile.dll_overrides]
xinput1_3 = "native"
```

Обмеження: такий профіль діє лише в одній пляшці, ним не можна поділитися, і він не застосовується, якщо Steam уже запущений (CLI про це попереджає).

## 2. Концепція профілю `cross-compat`

Профіль — окремий файл, яким можна ділитися. Він не прив'язаний до пляшки і описує гру незалежно від того, де вона встановлена.

### 2.1. Як профіль знаходить гру

| Ключ | Для чого | Приклад |
|---|---|---|
| Steam appid | ігри зі Steam | `413150` |
| хеш exe | ігри поза Steam, різні версії однієї гри | SHA-256 головного `.exe` |
| назва exe | запасний варіант, найменш надійний | `Game.exe` |

**[узгодити зі Спринтом 7]** які саме ключі підтримуються, що робити, коли збігається кілька профілів, і чи хешується весь файл.

### 2.2. Що містить профіль

| Поле | Значення | Відповідник зараз |
|---|---|---|
| бекенд | `d3dmetal` або `dxvk` (Direct3D 10/11) | `backend` у `LaunchProfile` |
| залежності | verbs з каталогу (`vcrun2022`, `dxvk`, …) | `cross deps install` |
| змінні середовища | `KEY = "VALUE"` | `env` |
| DLL overrides | `dll = "native" / "builtin" / …` | `dll_overrides` |
| аргументи | аргументи гри | `args` |
| версія Windows | 7/8/10/11 | `cross bottle preset … windows` |
| прапорці продуктивності | msync/esync, Metal HUD, MetalFX, обмеження ядер CPU | `--msync`, `--metal-hud` (решта — Спринт 7) |
| статус | зелений / жовтий / червоний | — |
| відомі проблеми | текст + посилання на issue | — |
| перевірено на | чип, macOS, двигун, дата | — |

**[узгодити зі Спринтом 7]** точні назви полів, формат файлу (TOML/YAML/JSON) і версія схеми.

### 2.3. Статуси

Статуси збігаються з критеріями тестової матриці (розділ 3 плану, [test-matrix.md](test-matrix.md)):

| Статус | Значення |
|---|---|
| **зелений** | запускається без ручних дій, стабільні 30+ FPS на M1 у 1080p на середніх налаштуваннях |
| **жовтий** | запускається, але з ручними діями (профіль їх прибирає), просіданнями FPS або дрібними артефактами |
| **червоний** | не запускається або неграбельна; для анти-чіту — «червоний (очікувано)» |

GUI (Спринт 6) показує цей статус на картці гри.

### 2.4. Звідки беруться профілі і що має пріоритет

Від нижчого пріоритету до вищого:

1. **вбудовані** профілі, які постачаються з cross-app;
2. **community-репозиторій**, що оновлюється окремо від релізів (як `steam-patches.toml`: лише https, лише новіша ревізія);
3. **локальний override** користувача в теці даних;
4. налаштування гри в конкретній пляшці (`cross steam profile`).

**[узгодити зі Спринтом 7]** розташування локальних файлів, адреса і формат community-репозиторію, як саме зливаються поля (заміна чи доповнення `env`/`dll_overrides`).

### 2.5. Безпека профілів із мережі

Профіль з community-репозиторію — недовірені дані. Ті самі межі, що вже діють для `steam-patches.toml`:

- заборонені змінні, які перенаправляють префікс або підвантажують бібліотеки: `WINEPREFIX`, `WINEARCH`, `WINE`, `WINESERVER`, `PATH`, `DYLD_*`;
- аргументи без пробілів і лапок;
- реєстр лише в дозволених гілках;
- залежності лише з нашого каталогу verbs; fallback на winetricks з мережевого профілю не викликається.

**[узгодити зі Спринтом 7]** перелік дозволених гілок реєстру для профілів.

## 3. Як написати профіль для гри

1. Створіть чисту пляшку: `cross bottle create test-<гра>`.
2. Запустіть гру без налаштувань і запишіть, що сталося (статус і помилки з логу).
3. Змінюйте по одному параметру, починаючи з найімовірнішого:
   - DX9/10/11 → спробуйте `--backend dxvk` (потрібні `cross engine install <двигун> --dxvk` і `cross deps install <пляшка> dxvk`);
   - помилки про `MSVCP140.dll` / `VCRUNTIME140.dll` → `cross deps install <пляшка> vcrun2022`;
   - гра не бачить версію Windows → `cross bottle preset <пляшка> windows 10`;
   - FPS → `--msync`, перевірка через `--metal-hud`.
4. Перевірте профіль на чистій пляшці ще раз: він має працювати без жодних ручних кроків.
5. Запишіть результат у форматі [тестової матриці](test-matrix.md#формат-запису-результату) і надішліть профіль через шаблон issue «Звіт про сумісність гри». **[узгодити зі Спринтом 7]** чи профілі приймаються через pull request у community-репозиторій.

## 4. Приклад (ілюстрація, не фінальний формат)

```toml
# [узгодити зі Спринтом 7]: назви полів і структура умовні.
[game]
name = "Half-Life 2"
steam_appid = 220

[launch]
backend = "dxvk"
deps = ["dxvk"]
args = ["-novid"]
env = { DXVK_ASYNC = "1" }

[status]
rating = "<green|yellow|red>"   # заповнюється за результатом тесту, тут не виміряно
tested = [{ chip = "<M1>", macos = "<26.x>", engine = "<wine-devel-11.18>", date = "<РРРР-ММ-ДД>" }]
known_issues = []
```
