# Телеметрія в cross-app

Телеметрія потрібна для бази сумісності: на яких Mac і з якими двигунами ігри запускаються, а на яких ні. Вона **вимкнена за замовчуванням**, вмикається лише явно і **нічого нікуди не надсилає**: сервера для прийому даних немає, мережевого коду в `cross-telemetry` теж немає. Події лише складаються в локальну чергу, яку можна будь-коли переглянути або видалити.

## Команди

```bash
cross telemetry status [--json]   # увімкнено чи ні, скільки подій у черзі, де лежать файли
cross telemetry enable            # дати згоду; виводить, що саме записується
cross telemetry disable           # відкликати згоду і видалити всю чергу
cross telemetry show              # черга як є: один JSON-об'єкт на рядок
```

Змінна оточення `DO_NOT_TRACK` зі значенням, відмінним від порожнього і `0`, зупиняє запис навіть після `enable`. `status` це показує.

## Файли

| Файл | Що в ньому |
|---|---|
| `~/Library/Application Support/cross-app/telemetry.toml` | `enabled` (згода) і `decided` (користувач уже обрав, тож GUI більше не питає) |
| `~/Library/Application Support/cross-app/telemetry/queue.jsonl` | черга подій, не більше 500; найстаріші відкидаються |

Файлу `telemetry.toml` немає, поки користувач нічого не обрав, і це означає «вимкнено». Зіпсований файл теж ніколи не вмикає запис. Змінна `CROSS_APP_HOME` переносить обидва файли разом з рештою даних.

## Що записується

Одна подія на запуск програми:

```json
{"schema":1,"kind":"launch","app_version":"0.0.1","macos":"26.5","chip":"Apple M1 Pro","engine":"wine-devel-11.18","backend":"dxvk","outcome":"success"}
```

| Поле | Значення | Як знеособлено |
|---|---|---|
| `schema` | версія формату (зараз `1`) | — |
| `kind` | `launch` | — |
| `app_version` | версія cross-app | — |
| `macos` | лише `major.minor` | без patch-версії, щоб не звужувати групу |
| `chip` | `Apple M<n>` + `Pro`/`Max`/`Ultra` | розібране значення, ніколи не сирий рядок `sysctl` |
| `engine` | id двигуна з вбудованого каталогу | будь-який інший id (локальний `catalog.json`) стає `custom` |
| `backend` | `d3dmetal` або `dxvk` | — |
| `outcome` | `success`, `exited_with_error`, `failed_to_start` | — |

**Не записується ніколи:** ідентифікатори встановлення чи пристрою, IP-адреси, імена користувача або хоста, шляхи, назви програм, ігор і пляшок, Steam appid, аргументи й змінні оточення, час події (порядок у черзі є, позначок часу немає).

Назва гри була б найкориснішою для бази сумісності, але її свідомо не збираємо: це вже інформація про поведінку людини. Якщо її колись додавати, то окремою згодою, а не розширенням цієї.

## Що відбувається при надсиланні

Нічого: надсилання не реалізоване, адреси сервера немає ні в коді, ні в конфігурації. Перш ніж його додавати, потрібні:

- сервер з HTTPS, який не логує IP-адреси, і опублікована політика приватності;
- надсилання пакетом у фоні, без повторних спроб у циклі, з очищенням черги лише після успішної відповіді;
- `cross telemetry show` має й далі показувати рівно те, що буде відправлено;
- окреме питання про згоду в майстрі першого запуску GUI (Спринт 6), яке показується лише поки `decided = false`.

## Підключення до запуску (ще не зроблено)

Бібліотека й CLI готові, але виклик під час запуску програми ще не підключено: файли запуску (`crates/cross-bottle/src/{exec,launch}.rs`, `crates/cross-cli/src/main.rs`) паралельно змінює інша гілка. Коли гілки зіллються, достатньо одного виклику після завершення програми, наприклад у `crates/cross-cli/src/bottle.rs::run_program`:

```rust
let outcome = match &result {
    Ok(status) if status.success() => cross_telemetry::Outcome::Success,
    Ok(_) => cross_telemetry::Outcome::ExitedWithError,
    Err(_) => cross_telemetry::Outcome::FailedToStart,
};
cross_telemetry::record_launch(dirs, runtime.engine_id(), Some(bottle.backend), outcome);
```

Тут `runtime.engine_id()` позначає умовний доступ до id двигуна пляшки. `record_launch` нічого не робить, якщо згоди немає: навіть `sysctl` і `sw_vers` тоді не запускаються. Будь-яка помилка лише пишеться в лог і ніколи не зриває запуск. Те саме варто додати в `cross steam launch` і в Tauri-команду запуску GUI.
