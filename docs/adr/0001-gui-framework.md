# ADR 0001 — GUI-фреймворк: Tauri 2

- Статус: прийнято (14.10.2026, Спринт 1)
- Контекст: `SPRINT_PLAN.md`, Спринт 6 (GUI), Спринт 9 (пакетування й автооновлення)

## Контекст

GUI потрібен для сценарію «встановив → запустив Steam → запустив гру» без терміналу. Головні екрани: бібліотека карток з обкладинками зі Steam CDN, сторінка пляшки, майстер першого запуску, логи в реальному часі, drag-and-drop `.exe`.

Ядро (`cross-core` та наступні крейти) не залежить від UI. Усе, що вміє GUI, доступне через CLI. Вибір фреймворку лишається оборотним: у разі заміни перепишеться лише `cross-gui`.

## Розглянуті варіанти

| | Tauri 2 | iced (pure Rust) |
|---|---|---|
| Сітка карток із зображеннями, анімації, темна тема | веб-стек, тут він найсильніший | можливо, але багато ручної роботи |
| Автооновлення з підписаними маніфестами | `tauri-plugin-updater` готовий | власна реалізація (Sparkle або самописне) |
| `.app` bundle, DMG, підпис і нотаризація | є в `tauri build` | власні скрипти |
| Нативний вигляд macOS (меню, vibrancy, Dock) | меню й нотифікації є, решта через плагіни або FFI | менше нативності, свій рендер |
| Тулчейн | Rust + Node (фронтенд) | лише Rust |
| Розмір і пам'ять | WKWebView, системний (вбудований рушій не постачається) | менший |
| Ризик | дві мови, IPC-межа | молодша екосистема віджетів, доступність (a11y) слабша |

## Рішення

Tauri 2 з веб-фронтендом. Rust-команди Tauri викликають `cross-core` напряму; фронтенд лишається тонким шаром над ними.

Причини: готові автооновлення й пакетування закривають половину Спринту 9, а карткова бібліотека з обкладинками значно дешевша у вебі.

## Наслідки

- З'явиться крейт `crates/cross-gui` у Спринті 6; до того каркас не додаємо.
- У репо додається JS-тулчейн (вибір пакетного менеджера і фреймворку фронтенду — окреме рішення на початку Спринту 6).
- Довгі операції (завантаження двигунів, інсталяція Steam) мають віддавати прогрес через канал подій у `cross-core`, а не через UI-специфічні виклики. Це вимога до API з Спринту 2.
- Якщо WKWebView стане вузьким місцем (наприклад, живі логи на тисячі рядків), віртуалізуємо список на фронті; перехід на iced розглядаємо лише за системних проблем.
