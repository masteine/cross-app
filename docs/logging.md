# Логи та діагностика

cross-app пише два види логів:

- **власний лог** `cross.log.<дата>`: що робила кожна команда;
- **вивід Wine** `run-<час>.log`: stderr програми, яку запустили через `cross run`.

Власний лог за замовчуванням детальний (рівень `debug`), щоб проблему можна було розібрати вже після запуску. Термінал при цьому лишається тихим.

## Де що лежить

```text
~/Library/Application Support/cross-app/
  logs/cross.log.2026-10-15             команди без пляшки (doctor, engine, diag)
  bottles/<id>/logs/
    cross.log.2026-10-15                команди над пляшкою (bottle, run, deps, steam)
    run-20261015-101500.log             вивід Wine для одного `cross run`
    steam.log                           вивід клієнта Steam (`cross steam launch`)
```

- **Щоденні логи:** зберігаються 14 днів.
- **Run-логи:** по 20 останніх на пляшку.

Старіші файли видаляються автоматично.

## Перегляд

```bash
cross logs                         # кінець сьогоднішнього загального логу
cross logs --bottle demo           # лог команд над пляшкою
cross logs --bottle demo --wine    # останній вивід Wine
cross logs --bottle demo --steam   # вивід Steam
cross logs --bottle demo --list    # усі файли з розмірами
cross logs --bottle demo -n 200    # більше рядків
cross logs --bottle demo -f        # стежити за новими рядками (Ctrl-C — вийти)
cross logs --bottle demo --wine --path   # лише шлях до файлу
```

Команда `cross logs` сама в логи нічого не пише.

## Скільки показувати в терміналі

| Прапорець | Термінал | Файл |
|---|---|---|
| (немає) | лише попередження й помилки | `debug` |
| `-v` | + основні кроки (`info`) | `debug` |
| `-vv` | + деталі (`debug`) | `debug` |
| `-vvv` | усе (`trace`) | `debug` |
| `-q` | лише помилки | `debug` |

Прапорці можна ставити будь-де: `cross -v bottle create demo` або `cross bottle create demo -v`.

- **Рівень файлу:** задається полем `log_level` у `config.toml` (за замовчуванням `debug`).
- **`RUST_LOG`:** перекриває обидва фільтри, наприклад `RUST_LOG=cross_steam=trace,info cross steam games demo`.

## Вивід Wine

За замовчуванням Wine мовчить (`WINEDEBUG=-all`). Для розслідування увімкніть потрібні канали лише для одного запуску:

```bash
cross run demo app.exe --wine-debug +err,+module    # stderr Wine піде в run-лог
cross logs --bottle demo --wine
```

Як працює run-лог:

- **Що куди йде:** stdout програми лишається в терміналі, stderr Wine записується в run-лог.
- **Ненульовий код виходу:** `cross run` друкує шлях до run-логу.
- **Вивід у терміналі:** щоб бачити stderr прямо в терміналі, додайте `--no-log`.
- **Вміст run-логу:** на початку — команда й змінні оточення, які задав cross-app; у кінці — код виходу й тривалість.

stderr пишеться напряму у файл, без проміжного каналу. Wine передає цей потік `wineserver` і всім програмам, які запускає, а вони можуть пережити `cross run`. Запис у канал, який уже ніхто не читає, вбив би їх сигналом SIGPIPE.

## Архів для звіту про помилку

```bash
cross diag                           # ./cross-diag-<час>.tar.gz
cross diag -o ~/Desktop/report.tar.gz
```

Архів містить:

- результат `cross doctor` (JSON);
- `config.toml` і локальні каталоги (`catalog.json`, `verbs.toml`, `steam-patches.toml`), якщо вони є;
- `engine.toml` кожного двигуна;
- `bottle.toml` кожної пляшки та її останні логи (3 щоденні, 3 run-логи, `steam.log`);
- останні загальні логи;
- список запущених пляшок.

Від кожного файлу береться не більше 2 МБ, з кінця.

## Що не потрапляє в логи

- **Оточення інших процесів.** Вивід службового `ps -E` (оточення всіх процесів користувача) ніколи не логується.
- **Секрети.** Значення змінних, чиї назви схожі на секретні (`TOKEN`, `SECRET`, `PASSWORD`, `KEY`, `AUTH`, `COOKIE`), замінюються на `<redacted>`: в аргументах команди, у змінних запуску й у збереженому виводі допоміжних команд.
- **Паролі.** cross-app їх ніде не збирає.

Шляхи файлів (з іменем користувача macOS) і назви програм у логах лишаються. Перегляньте архів, перш ніж кудись його надсилати.
